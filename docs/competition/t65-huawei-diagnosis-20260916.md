直接 GET 的11条历史华为记录均只有 `raw_result={"errors":[],"failed_cases":[]}`，缺少成功用例编号、shape、dtype、stride、路由分布、T_base、T_opt、重复样本及聚合权重。**返回成功用例明细0条，不代表实际执行0条；实际用例数未知。** `execution_time_ms` 是整条评测记录时长，不能当作单个 kernel 延迟，也不能由 score 下降断言 T_opt 增加8.60%。

已沿官方公开前端实际 import 链检查 race-detail → S2Track1 → SubmitTab 及 API helper：`index-CZzTlpqt.js:28188–28194`只有提交列表 GET；`SubmitTab-DV6Q55bs.js:239–246`失败详情读取现有 raw_result，`:724–727`成功项仅显示 speedup。现有 CLI 原样保留 gpu_results/raw_result。在这个已检查范围内未发现额外只读详情接口；不据此断言后台私有接口不存在。

差异仅为 hidden 块调度：E9 每 token 串行扫描 hidden；E10 将起点改为 `pid1*2048`、步长改为 `num_programs(1)*2048`，并使用 `gy=min(cdiv(hidden,2048),255)`、`gx=min(tokens,max(1,65535//gy))`。BLOCK、slot 标量读取、`dst>=0`条件、fp32运算/累加顺序和各输入 stride 保持一致，昆仑成员逐字节冻结。

以静态示例 T32/H8192/K8 为例，program数32→128，但两版均为128个逻辑hidden块、1024次slot迭代；T32768/H2049/K1 为32768→65534个program，逻辑块仍65536。示例不是平台隐藏用例，逻辑工作量相同也不代表实际内存流量相同。调度、编译、缓存及目标芯资源开销均需昇腾 IR/profile 验证。

## 5. 下一步依赖实际昇腾执行入口

取得已有授权的昇腾 SSH alias/固定源码执行 endpoint，或平台两条 validation 的配对成功用例导出后，按以下顺序推进：

1. 固定 E9/E10 上述字节、同一reference与测试输入，记录设备、驱动、SDK、Torch/Triton版本及source/test哈希；先验证契约和正确性。
