### 赛题状态机（6 态）

| 状态 | 含义 |
| --- | --- |
| 待攻克 | 无人到达性能门槛，适合抢首发 |
| 竞争中 | 已有有效提交（全芯 ≥0.1x），继续刷平均加速比 |
| 评审中 | 批次截止、关闭提交入口，进入专家审核 |
| 已攻占 | 评审完成，认证榜单第一名团队 |
| 仅攻克 | 只有攻克荣誉（时间线首个），未产生有效攻占 |
| 已失效 | 全程无人有效攻克/攻占 |

- **攻克按提交时间线**评（首个有效过线提交）；**攻占按团队**评（评审后榜单第一）。
- 评审重点两个：榜单从前往后找"真正有效的第一名"；按时间找首个有效提交。
- 无效提交（正确性不过或任一芯片 <0.1x）即使平均加速比高、登顶榜单，
  也会被判定无效、失去攻占资格。

### 排名三关与公式

1. 正确性：与 torch 参考在题面容差内一致（题面没给容差的题要求完全一致）。
2. 性能门槛：**每一颗芯片**加速比 > 0.1x（torch 5s 的题你须 <50s；
   任一芯片不达标 → 该次提交无法参与排名）。
3. 排序：平均加速比降序；同分先提交者优先。
   **平均加速比 = 各芯片（PyTorch 参考耗时 / 提交代码耗时）的算术平均。**
   官方策略口径：先保证全芯片可用，再在平均加速比上持续刷新榜单。

### 提交规则

- ZIP 包内：`<Kernel_Name>.py` 跨芯片通用代码（**必需**）+
  `<Kernel_Name>_<chip>.py` 芯片特化（可选，芯片名在提交入口可见）。
- 评分时优先用芯片特化文件，未提供的芯片回落通用文件。
- 每日默认 15 次、**全队所有题共享**；队伍满 5 名成员可升至 30 次；
  两次提交间隔 > 2 分钟。
- 平台排行榜只展示芯片通过数 = 8 且每芯 >0.1x 的提交。

## 二、SGLang kernel 体系要点（背景 + 长期相关）

- kernel 库按功能分 21 个 domain、约 502 个算子文件；六大功能组
  （attention / KV cache / GEMM+quant / MoE / 通信 / 推测解码等）。
- 核心原则"一个逻辑算子，多个实现"：统一入口
  `sglang.kernels.ops.<group>.<operator>` + KernelRegistry；
  后端含 torch 基线、长期存在的 triton/JIT 后端，以及**新增 agent-harness
  后端（KDA 等）**——KDA backend 已有 9 个算子，agent 生成的 kernel 是
  一等公民，与自有代码互不干扰。
- JIT kernel：源码 + 编译 flag + 目标硬件 + 导出方式收成 BuildSpec key，
  过三级缓存；实测 H100 冷启 5.26s / 命中 0.02s / B200 0.05s；
  "只编译当前 workload 需要的，缓存为已验证工件"。
- attention 一类 24 个注册后端（Dense / MLA / Sparse+平台）；通信侧
  CustomAllreduce V2（OneShot push/pull、TwoShot 模式），8×B200 bf16
  16MB 消息比 V1 快 2–3 倍；案例：Qwen TP8 + CUDA Graph 端到端 ~18%。
- Reward-hacking 三教训（官方明示的测试纪律，值得进我们的 bench 检查单）：
  1. **路径变了**：轻量 wrapper / 静默 fallback 造成假加速 → 两个版本走
     同一 API，确认新 kernel 真的被派发；
  2. **测试变了**：换编译 flag / 放宽容差 / 挑 shape → 冻结 flag、参考实现
     和测试 shape 再调优；
  3. **只有 kernel 赢了**：kernel 快但 cache 压力或后续工作拖慢 serving →
     回放 CUDA Graph、测端到端吞吐。
  金句：A benchmark win is only a candidate. The full serving result is
  the decision.（赛题全部来自真实 SGLang workflow，平台评测即端到端代理，
  官方明示"可放心优化，收益会反映到 serving"。）

## 三、代码仓贡献规范（flaggems_sglang 负责人口播）

- 三级派发（按函数名模块发现）：
  Priority 0 通用 `src/flaggems_sglang/ops/`（device-agnostic Triton）→
  Priority 1 芯片特化 `runtime/backend/_<chip>/ops/`（硬件 intrinsics）→
  Priority 2 架构特化（如 Hopper WGMMA）。与我仓现结构完全一致。
- 硬性要求：每个 op 文件必须定义 `__all__`；全源文件 Apache 2.0 头；
  pre-commit 强制（79 列、flake8/black/isort）；CI 按后端跑 pytest
  （`pytest -q tests/test_<op>.py --quick` 本地预跑）+ benchmark shapes。
- 两种集成方式：SGLang 插件机制（零改代码自动 fallback 到本仓库算子）/
  直接 `import` 调用。
- **官方明确鼓励两种提交形态**：batch-1 有队伍只交一个通用文件拿到全场
  最佳；也有通用 + 逐芯特化的。两种都收（特化增加工作量但加速比高即可）。
- 比赛有截止日、算子库没有：获奖算子赛后会进真实推理场景使用，
  PR 按 CI 规范走。
