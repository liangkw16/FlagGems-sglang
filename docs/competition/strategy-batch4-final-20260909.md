## 二、根因一：燧原 grid 超发（跨 11 题的系统性缺陷）

### 2.1 厂商文档硬事实

燧原 TritonGCU 官方性能优化指南明确：

> 在当前 GCU300 硬件平台上，因为 **kernel 启动开销无法被完全掩盖**，使得
> Triton kernel 以大于 GCU 硬件资源数量的 GridDim 和 BlockDim 并行执行时，
> 会引入额外的调度开销，从而增加算子执行时间，降低性能，**这一性能损失在
> kernel 计算量较小时尤为明显**。因此建议将 kernel 间的并行度，尽可能以
> **循环方式放入 kernel 内**。

推荐 GridDim：**GCU300 = 6（nw=4）/ GCU400 = 24（nw=8）**，硬件仅 24 个 SIP。
另：`num_stages>=3` 开启 pingpong（2D 计算默认推荐，实测 +15%）；
GCU 的 BLOCK_SIZE 倾向**远大于** GPU。

### 2.2 我方实际 grid

| 算子 | 燧原 grid | 量级 | 超发倍数 |
| --- | --- | ---: | ---: |
| act_and_mul | `min(rows*ceil(H/4096), 65535)` | 1e4 | ~2700x |
| chunked_embedding_lora_a | `min(total_tokens, 65535)` | 1e3–1e4 | ~1000x |
| causal_conv1d_update | `min(batch*head_tiles, 65535)` | 1e3 | ~100x |
| fla_layernorm_gated | `(rows,)` | 1e3 | ~100x |
| ernie45_rope_fused | `(T, cdiv(n_h,tile))` | 1e3 | ~100x |

**全部 enflame vendor 中，只有 2 个（draft_topk1 / gate_up_lora_b）用了
`tl.range`；0 个在循环上设 `num_stages`（即 pingpong 全线未开启）。**

### 2.3 交叉验证：显式 `num_warps` 与燧原分数的负相关

| 组 | n | 燧原分数中位数 | >1.5x 占比 |
| --- | ---: | ---: | ---: |
| 未写 `num_warps`（用后端默认） | 9 | **2.077** | 6/9 |
| 显式钉住 `num_warps` | 20 | **0.732** | 4/20 |

中位数差 **2.84x**。此前 T19-E5/T51-E5 已两次平台实证"去掉显式 launch 参数
燧原 +38%"，但该结论只被应用到那两题，未推广。

注：这是相关性观察（钉 warps 的多为 dot 类重算子），不单独作为因果证明；
但它与厂商文档的因果机制方向一致，且 grid 超发是独立可验的硬事实。

### 2.4 统一修复形态（persistent + pingpong）

```python
_GRID = 24                      # 一次占满 SIP，不超发
grid = (min(total_tiles, _GRID),)
# kernel 内：
for tile in tl.range(pid, total_tiles, tl.num_programs(0), num_stages=3):
    ...                         # num_stages>=3 开 pingpong
# launch 不写 num_warps（让 GCU 后端选官方默认）
```

这是**一处形态、11 题复用**的改动，且 T51 的 `(rows,)`→persistent 是同一
把钥匙（T51 目前靠慢窗守榜，结构上并未真正拿下燧原）。

## 三、根因二：T48 的维度角色反转（单题最大杠杆）

T48 是 12 题里唯一**八芯全线**落后 3–8x 的题（天数 5.1x / 沐曦 4.4x /
燧原 32x / 海光 7.8x / 昆仑 3.4x / 华为 3.1x / A 5.2x / B 4.7x）。
八芯同步落后 ⇒ 与任何单芯 lowering 无关，是 generic 结构问题。

对照两题的数学定义：

| | 归约维（BLOCK_K 该管的） | 输出维（BLOCK_N 该管的） |
| --- | --- | --- |
| T47 expand `x[S,rank] @ W[rank,out]` | rank，**小** 8–64 | out_dim，**大** 1e3 |
| T48 shrink `x[S,K_in] @ W[rank,K_in]ᵀ` | K_in，**大** 512–4096 | rank，**小** 16–64 |

**两题的维度角色恰好互换**，而 T48 的 generic 直接沿用了 T47 的
`BLOCK_N=128 / BLOCK_K=32`，并把 `RANK=K`（K_in）传进归约轴：

| K_in | rank | K 循环趟数 @32 | @256 | dot 列填充浪费 @128 | @next_pow2 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 512 | 16 | 16 | **2** | 87.5% | **0%** |
| 1024 | 64 | 32 | **4** | 50.0% | **0%** |
| 2048 | 32 | 64 | **8** | 75.0% | **0%** |
| 4096 | 16 | 128 | **16** | 87.5% | **0%** |

即**同时**承担 8–16 倍多的循环趟数与 2–8 倍的空列 dot。与"八芯一致落后
3–8x"在量级上吻合。

修复（单变量、纯 generic、不动 vendor）：
`BLOCK_N = max(16, next_pow2(rank))`；`BLOCK_K = 128 或 256`（走真实 K_in）。

历史账本把 e2/e3 的失败归因为"段内多 tile 缺失"并关闭了该方向——那是
**wrapper 覆盖 bug**，与本条 tile 几何错配是两件事，不构成本轴的证伪。

T48 只要修对，均值 4.81 → 理论 31.19（榜首 26.94，REAL），**可夺 Top1**。
